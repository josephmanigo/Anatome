# 3. Numbered material findings

1. **P1 — Keep narration captions visible while the learner manipulates anatomy.** In `pneumothorax-1440.png`, the initial activity viewport shows no narration caption. `ShowWorkspace` appends `caption` after the demonstration, finish, inspection, isolation, restore, browse, settings and manipulation-hint controls. That places live narration text below the scroll viewport even at 1440 × 1000. Scrolling down to read it also hides the current objective and status. This breaks the practical value of the approved caption accessibility feature. **Pointers:** [LabUI.cs:173](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.cs:173>), with caption updates at [LabUI.cs:224](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.cs:224>). **Bounded correction:** put live captions in a reserved, wrapping area outside the scrolling control list; account for its height in the unobscured 3D area and allow the configured caption scale. Do not overlay the specimen or procedure tools. **Resolution evidence:** active narrated practice with a nonempty sentence at 1440 × 1000 and 960 × 540, including 150% UI text and 170% caption text; captions remain visible while the control rail scrolls and do not clip or cover essential anatomy/tools.

2. **P1 — Complete the XR pointer events needed for settings sliders.** `RayPointer` dispatches only `pointerClickHandler` when `press` is true. `LabHandInteractor` supplies only `trigger && !previousTrigger`, so the UI receives no held-drag or release state. The bundled Unity `Slider` implements its value interaction in `OnPointerDown` and `OnDrag`, not `OnPointerClick`. Therefore the inspected controller-ray path can click buttons but cannot directly adjust slider values such as narration volume, text size, caption size, render scale or table height. This is a source-confirmed interface defect, not a claim that a physical headset was tested. **Pointers:** [LabUI.cs:240](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.cs:240>), [LabUI.cs:248](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.cs:248>), [LabHandInteractor.cs:19](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Scripts/LabHandInteractor.cs:19>), and the locally installed `com.unity.ugui@b95364aab964/Runtime/UGUI/UI/Core/Slider.cs:651-672`. **Bounded correction:** provide a complete retained pointer lifecycle for each controller, including down, drag and up, or an equivalent slider interaction that handles press/hold/release deliberately. Preserve button clicks and panel scrolling; ensure a slider drag is released when the ray leaves the control or the panel changes. **Resolution evidence:** a runtime input-level check through the same ray entry point changes a slider, continues changing it while held, stops on release, and leaves ordinary button clicks/scrolling working. Physical Quest confirmation remains required later.

3. **P2 — Size the settings header to its text rather than a fixed height.** The runtime report flags both `Make the lab yours` and `Windows · Windows balanced` as overflowing in `settings-1440`. `RenderSettingsPage` reserves `130 * TextScale` for a two-line header inside a column with 28-pixel padding and six-pixel spacing. The rendered words happen to remain legible with TMP's overflow mode; that is not a resolved layout constraint, and longer profile names further stress it. The 150% capture does not show the same visible collision, so this finding is specifically the reported base-size header allocation, not a claim that all large text overlaps. **Pointer:** [LabUI.Settings.cs:20](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.Settings.cs:20>). **Bounded correction:** derive the reserved heading height from the preferred heights of its title/profile text and its padding/spacing, then position both settings panes below that result. Retain wrapping for a valid long profile name. **Resolution evidence:** recapture both existing settings sizes and rerun the text-overflow check with zero header errors; also exercise a long profile name at 150% text size without overlap or loss of category/control access.

4. **P2 — Bring the complete active tool tray into the initial case viewport.** In `pneumothorax-1440.png`, the front white-barrel instrument and the tray extend beneath the bottom save-status band/window boundary. The starting instruction asks the learner to select an instrument from this tray, but its nearest instrument is only partly visible. The canonical specimen is visible; the defect is the case equipment composition. `Configure` places the tray/tools at fixed offsets while `Page` changes only the viewport rectangle, without fitting the combined specimen/equipment bounds. **Pointers:** [ProcedureWorkbench.cs:68](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/ProcedureWorkbench.cs:68>), [ProcedureWorkbench.cs:73](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/ProcedureWorkbench.cs:73>), and [LabUI.cs:51](<C:/Users/My Pc/Downloads/new/unity/ThoraxLab/Assets/ThoraxLab/Learning/LabUI.cs:51>). **Bounded correction:** adjust the initial desktop case framing or tray placement so the active specimen and every instrument are wholly inside the usable 3D area, including any reserved caption area from finding 1. Keep the specimen large enough to inspect; a clearly visible focus-tray control is an acceptable supplement if one view cannot fit both usefully. **Resolution evidence:** the initial pneumothorax view at both desktop sizes shows the whole tray/tool set without footer/caption occlusion; the learner can select each instrument from the visible viewport. This correction does not require rebuilding the schematic instruments into clinical models.
